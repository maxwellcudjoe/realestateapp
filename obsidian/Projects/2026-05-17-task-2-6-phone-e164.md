# Task 2.6 — E.164 Phone Validation

Closes gap **R17** (phone field accepted garbage with only `min(7).max(50)`).

## Change

`stepPersonalSchema.phone` now refines with `libphonenumber-js`
`isValidPhoneNumber(value, 'GB')`. The API additionally parses the value via
`parsePhoneNumber(value, 'GB')` and stores the **E.164 form** (`+44…`) so
all phone numbers in the DB are normalised — easier for SMS, dialler links,
search, and de-dup.

## Behaviour

| Input | Stored |
|---|---|
| `07911 123 456` | `+447911123456` |
| `+44 7911 123 456` | `+447911123456` |
| `not-a-number` | rejected with `"Enter a valid phone number…"` |

Library knows about the UK "fiction-only" 7700-9xxxxxx range and rejects those.
The default country is GB (matches the platform's audience). When the
addressLine country picker ships (Task 2.5), this default will pivot.
